## App
- [x] Linux audio: PulseAudio protocol (works with PipeWire's pipewire-pulse) with ALSA fallback.
- [ ] Output latency (decide the approach). Measured situation on the dev machine: the default
      output is Bluetooth headphones (A2DP, AAC), which alone add ~150–250 ms; nothing in software
      removes that. Kadence itself asks for 2 × 512 frames (~21 ms) through the PulseAudio layer,
      plus PipeWire's graph quantum (1024 frames, ~21 ms): wired output should be ~40 ms total.
      Options, best first:
      1. Measure: show the real output delay per device (wired jack vs Bluetooth) before choosing.
      2. Low-latency setting: request 128–256 frames (choice 128/256/512, fall back if refused);
         wired output then ~8–15 ms. Cost: more wake-ups, risk of crackles on a busy machine.
      3. Native PipeWire output (cpal `pipewire` feature) as the Linux default, PulseAudio/ALSA as
         fallbacks: one buffering layer less (~5–10 ms) and exact timing. Building needs libclang
         (not installed on the dev machine; the Flatpak SDK has it; CI needs libpipewire-0.3-dev +
         libclang-dev).
      4. Notice on the LCD when the output is Bluetooth ("adds ~0.2 s delay; use wired output").
      Not worth it: JACK (goes through PipeWire anyway), raw ALSA (takes the card exclusively).
      The pendulum, LEDs and Time Check already compensate for the reported delay.
